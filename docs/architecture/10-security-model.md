# 10 — Security Model

## 1. Overview

Bugzilla implements a multi-layered security model protecting:
1. **Authentication** — who can access the system
2. **Authorization** — what each user can see and do
3. **Data integrity** — preventing data corruption
4. **Transmission security** — protecting data in transit
5. **Code security** — preventing injection attacks

---

## 2. Authentication Security

### 2.1 Password Storage

**Algorithm**: bcrypt with automatically increasing cost factor  
**Module**: Perl's `Crypt::Bcrypt` or equivalent

```perl
# Password hashing on creation/change:
$cryptpassword = Crypt::Bcrypt::bcrypt($password, generate_random_salt());

# Verification:
Crypt::Bcrypt::bcrypt_check($input_password, $stored_hash)
```

**Constants:**
- `PASSWORD_DIGEST_ALGORITHM` — hash algorithm identifier
- `PASSWORD_SALT_LENGTH` — salt length in bytes
- `USER_PASSWORD_MIN_LENGTH = 6` — minimum password length

### 2.2 Account Lockout

```perl
# Constants in Constants.pm:
MAX_LOGIN_ATTEMPTS    = 5   # After 5 failures, account is locked
LOGIN_LOCKOUT_INTERVAL = 30  # Minutes before lockout resets
```

Implementation: Failed login attempts are tracked in the `profiles` table (`login_failed_count`, `lock_until`). After `MAX_LOGIN_ATTEMPTS` failures within `LOGIN_LOCKOUT_INTERVAL` minutes, the account is locked until the interval passes.

**Result**: `AUTH_LOCKOUT` returned, user cannot log in even with correct password.

### 2.3 Session Management

**Cookie-based sessions** (`logincookies` table):

```
Cookie name: Bugzilla_login + Bugzilla_logincookie
Attributes:
  - HttpOnly (cannot be read by JavaScript)
  - Secure (HTTPS only, configurable)
  - SameSite=Lax
```

**Session constants:**
- `MAX_LOGINCOOKIE_AGE` — days before session cookie expires
- `MAX_SUDO_TOKEN_AGE` — hours before sudo escalation expires

**IP restriction option**: Sessions can be optionally locked to the creating IP address (`restrict_ipaddr` column in `logincookies`).

### 2.4 API Key Security

```sql
user_api_keys:
  api_key    VARCHAR(40)  -- Stored as SHA-1 hash, not plaintext
  revoked    BOOLEAN      -- Can be individually revoked
  last_used  DATETIME     -- Tracked for audit
  last_used_ip VARCHAR(40) -- IP tracking
```

Keys are shown only once at creation time. The stored value is hashed.

### 2.5 CSRF Protection (Tokens)

Every state-changing form includes a CSRF token:

```perl
# In templates, forms include:
[% PROCESS global/hidden-fields.html.tmpl %]
<!-- Generates: -->
<input type="hidden" name="token" value="[% token %]">

# Server-side verification:
check_hash_token($token, ['bugchange', $bug_id]);
```

**Token types and their purposes:**
```
session  → Validate form submissions
account  → Email verification for account creation
emailold/emailnew → Email address change confirmation
password → Password reset link
sudo     → Admin sudo action escalation
```

Tokens are generated with `Math::Random::ISAAC` (CSPRNG) and `Digest::SHA::hmac_sha256_base64` for signed tokens.

## 3. Authorization Security

### 3.1 Permission Check Hierarchy

Every sensitive operation goes through explicit permission checks:

```perl
# Example: editing a bug
$user->can_edit_bug($bug)
     → checks: is bug in a product user has editbugs permission for?
     → checks: is bug in a group the user is in?
     → checks: is user the assignee or reporter?

# Example: seeing a bug
$user->can_see_bug($bug_id)
     → checks: is bug restricted to a group?
     → if yes: is user in that group?
     → if no: can user see bugs in this product?
```

### 3.2 SQL-Level Security (Group Filtering)

The search engine always adds security JOINs to ensure users never see bugs they shouldn't:

```sql
-- Simplified security SQL generated by Bugzilla::Search:
SELECT DISTINCT b.bug_id
FROM bugs b
LEFT JOIN bug_group_map bgm ON b.bug_id = bgm.bug_id
LEFT JOIN user_group_map ugm ON bgm.group_id = ugm.group_id
    AND ugm.user_id = ?
WHERE 
  -- Bug either has no group restriction
  (bgm.group_id IS NULL 
   -- OR user is in the restricting group
   OR ugm.user_id IS NOT NULL)
  -- AND other search conditions
```

This ensures that even if application logic has a bug, the SQL itself enforces visibility rules.

### 3.3 Group Access Control Levels

```
CONTROLMAPNA        = 0  → Bug cannot be placed in this group for this product
CONTROLMAPSHOWN     = 1  → Bug CAN be placed in group (user's choice)
CONTROLMAPDEFAULT   = 2  → Bug is placed in group by default
CONTROLMAPMANDATORY = 3  → All bugs in product MUST be in this group
```

**Example**: A "Security" group with `CONTROLMAPMANDATORY=3` for a product means all bugs in that product are automatically restricted to the Security group. Only security team members can see them.

### 3.4 Per-Product Privileges

```perl
PER_PRODUCT_PRIVILEGES = ('editcomponents', 'editbugs', 'canconfirm')
```

These privileges can be granted globally (via `groups` table) OR per-product (via `group_control_map.canedit`, `.editbugs`, `.canconfirm` columns). A user with global `editbugs` can edit any bug, but `editbugs` granted per-product only allows editing bugs in that specific product.

## 4. Input Validation & Injection Prevention

### 4.1 Perl Taint Mode

Bugzilla runs with Perl's taint mode enabled, which tracks "tainted" (user-supplied) data and prevents its use in sensitive operations without explicit untainting:

```perl
# All user input starts as tainted
my $bug_id = Bugzilla->cgi->param('id');  # TAINTED

# Must be explicitly untainted before DB use:
detaint_natural($bug_id);   # removes taint if it's a natural number
trick_taint($value);        # removes taint trusting the caller
```

**`Bugzilla::Util` untainting functions:**
- `detaint_natural($val)` — only valid if it's a non-negative integer
- `detaint_signed($val)` — only valid if it's an integer (positive or negative)
- `trick_taint($val)` — explicitly trusts caller's validation

### 4.2 SQL Injection Prevention

All database queries use **parameterized queries** (DBI placeholders):

```perl
# SAFE — parameterized:
$dbh->selectrow_array(
    'SELECT * FROM bugs WHERE bug_id = ?',
    undef,
    $bug_id  # placeholder prevents injection
);

# Never concatenated:
# 'SELECT * FROM bugs WHERE bug_id = ' . $bug_id  # NEVER DONE
```

The `Bugzilla::DB::QuoteIdentifier` module handles safe quoting of column/table names when those need to be dynamic.

### 4.3 XSS Prevention

**Template Toolkit auto-escaping**: By default, all variables in TT templates are HTML-escaped:

```
[% bug.short_desc %]         → auto HTML-escaped
[% bug.short_desc | html %]  → explicit HTML escape
[% bug.url | none %]         → explicitly DISABLE escaping (trusted content)
[% comment.text | quoteUrls %]  → converts URLs to links, then HTML-escapes
```

**JavaScript context escaping**:
```
[% variable | js %]          → JavaScript-safe (escapes quotes, backslashes)
[% variable | json %]        → JSON-safe encoding
```

**Content Security Policy**: Set via Apache `.htaccess`:
```apache
Header always set Content-Security-Policy \
  "default-src 'self'; \
   script-src 'self' 'unsafe-inline'; \
   style-src 'self' 'unsafe-inline'; \
   img-src 'self' data:;"
```

Note: `unsafe-inline` is currently required due to inline scripts in templates — a known limitation.

### 4.4 Email Injection Prevention

Email headers are validated and sanitized before use in outbound email:
- Newlines stripped from all user-provided header values
- Email addresses validated against RFC 2822 pattern
- Reply-to headers sanitized

## 5. Transmission Security

### 5.1 HTTPS Configuration

Bugzilla enforces HTTPS via:

```apache
# .htaccess:
Header always set Strict-Transport-Security \
  "max-age=31536000; includeSubDomains"
```

`MAX_STS_AGE` constant controls the HSTS max-age value.

### 5.2 Secure Cookie Flags

```perl
# In Bugzilla::Auth::Persist::Cookie:
$cgi->cookie(
    -name     => 'Bugzilla_logincookie',
    -value    => $cookie_value,
    -httponly => 1,           # No JS access
    -secure   => $params->{ssl_redirect} ? 1 : 0,  # HTTPS only
    -samesite => 'Lax',       # CSRF protection
);
```

## 6. Sensitive Data Handling

### 6.1 Private Comments

Comments marked `isprivate=1` are:
- Not indexed in `bugs_fulltext.comments_noprivate`
- Only visible to members of the `insidergroup` group
- Clearly marked as private in the UI

### 6.2 Sensitive Bug Visibility

Bugs restricted to security groups:
- Never appear in non-member searches
- Never appear in non-member "related bugs" suggestions
- Cannot be linked from public bug tracker links (returns 401)
- Member count not revealed to non-members

### 6.3 User Privacy

Email addresses:
- Not exposed to logged-out users (if `require_login` is enabled)
- Partially obscured in some contexts
- Never included in Atom feed output
- API `get_user` method respects privacy settings

## 7. Audit & Compliance

### 7.1 Bug Activity Log

Every field change is logged in `bugs_activity`:
```sql
INSERT INTO bugs_activity
  (bug_id, who, bug_when, fieldid, added, removed)
VALUES
  (12345, 42, NOW(), 5, 'IN_PROGRESS', 'CONFIRMED')
```

This is **immutable** — changes cannot be deleted or edited.

### 7.2 Admin Audit Log

Administrative changes (product creation, group changes, user management) are logged in `audit_log`:
```sql
INSERT INTO audit_log
  (user_id, class, object_id, field, removed, added, at_time)
VALUES
  (1, 'Bugzilla::Product', 42, 'name', 'OldName', 'NewName', NOW())
```

### 7.3 Login Event Tracking

`logincookies` table records every session creation with IP and timestamp.
`user_api_keys.last_used` and `last_used_ip` track API key usage.

## 8. Security Vulnerabilities & Known Limitations

| Area | Issue | Severity |
|---|---|---|
| Content-Security-Policy | Requires `unsafe-inline` for scripts | Medium |
| Password policy | Minimum length only 6 chars (configurable) | Low |
| LDAP injection | LDAP queries not parameterized in some paths | Historical concern |
| Information disclosure | Error messages may reveal system details | Low |
| Rate limiting | No built-in API rate limiting | Medium |
| Dependency age | CPAN modules may be outdated | Variable |

## 9. Modern Security Improvements for Replacement System

| Legacy | Modern |
|---|---|
| bcrypt passwords | argon2id (memory-hard, quantum-resistant) |
| Cookie sessions | httpOnly JWT refresh token + short-lived access token |
| Manual CSRF tokens | SameSite=Strict cookies + CSRF middleware |
| Perl taint mode | TypeScript type system + input validation schemas (Zod) |
| Template auto-escape | React JSX auto-escaping by default |
| No rate limiting | Redis-based sliding window rate limiter |
| No 2FA | TOTP + WebAuthn required for admins |
| No audit trail API | Event sourcing with queryable audit log API |
| Basic CSP | Strict CSP with nonce-based inline scripts |
| No security headers | Helmet.js (comprehensive security headers) |
| Manual permission checks | Declarative RBAC middleware (Casl.js) |
